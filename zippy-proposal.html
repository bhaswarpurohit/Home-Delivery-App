06 Architecture Diagram 2: 10-Minute Hyperlocal Dispatch Waterfall

Achieving a 10-minute arrival SLA requires searching tight, localized nano-markets rather than broad citywide radiuses. The sequence below illustrates the chronological execution pipeline from checkout to completion:

Figure 2: Real-Time Sub-10 Minute Dispatch Waterfall & Arrival Sequence
Chronological execution pipeline coordinated across PostGIS spatial indexing, BullMQ distributed timers, and Twilio voice relays.
T = 0s to 5s
🛒📱 1. Instant Checkout & Favorite Scan
Customer completes sub-45s 3-tap booking via Razorpay native UPI. System instantly checks if customer has a previously rated 5-star favorite helper online within corridor, granting an exclusive 30-second priority reservation window.
T = 5s to 50s
📡🔔 2. Primary Nano-Market Corridor (800m)
PostGIS executes sub-5ms ST_DWithin spatial query across ONLINE verified partners within 800m. BullMQ locks booking to Candidate 1 for 45s, triggering a high-priority FCM push with a loud 45-second audio ringtone modal.
T = 50s to 9m
🛵📞 3. Secondary Cascade & In-Transit
If Candidate 1 times out or declines, offer instantly cascades to Candidate 2 or auto-expands to 1.5km (ETA 15m). Live GPS radar route displays helper's movement with Twilio/Exotel virtual voice bridge active to protect private numbers.
T = 10m to Finish
🛡️📍 4. 200m Geofence Lock & Dual-OTP
Server cryptographically verifies device GPS is strictly within 200m of customer address before accepting Start OTP. End OTP finalizes the job, settles partner ledger, and automatically credits ₹50 compensation if SLA exceeded.

Authoritative Finite State Machine (FSM) State Table:

State Trigger Event Server Verification Logic Next State
REQUESTED Customer 3-tap checkout Razorpay signature verified via server webhook; creates reservation lock. SEARCHING
OFFERED PostGIS 800m query match BullMQ locks helper; 45s audible modal countdown initialized. IN_TRANSIT
ARRIVED Helper taps arrival Server computes GPS distance; rejects if >200m from destination. IN_PROGRESS
COMPLETED End-job OTP verified Redis compares code; ledger calculates duration, payout & opens rating. SETTLED
